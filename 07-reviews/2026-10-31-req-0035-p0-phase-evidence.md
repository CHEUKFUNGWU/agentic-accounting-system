## Deviations and owner-ratification items

1. **PostgreSQL 15.17 locally, work order specifies 16+.** The dual-DB matrix ran green against local PG 15.17 (homebrew). The P0 code uses nothing version-specific; the P2 goose/schema work should be validated on 16+ (or the owner confirms 15.x is acceptable for the matrix).
2. **design.md amended in this branch** (work order names design.md authoritative for interfaces): (a) `Round` now returns `(Money, error)` — Python quantize raises `InvalidOperation`, and a silent default would hide money corruption; (b) `fixtures/` and `tools/` added to the module map — the work order's deliverable 2 needs a recorded home. Both are documented in the design doc itself. Owner: ratify or direct reversion.
3. **Money module exceeds "one demonstration fixture"**: a full parity implementation shipped at P0 rather than an echo demo, because the harness demo is only meaningful against a real ported module and money is the ADR's top-risk parity surface (345 decimal touchpoints). Gate satisfied either way (three commands green + 112/112 replay).
4. **Parse grammar scope exclusions** (documented in money.go, fixture-pinned where both sides agree): non-finite specials (`Infinity`, `NaN`) and exponents beyond the context Emax/Emin (±999999) are rejected; Python constructs such values but its arithmetic traps on them, and no money path produces them.
