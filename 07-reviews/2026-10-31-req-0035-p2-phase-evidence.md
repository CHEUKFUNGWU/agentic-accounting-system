## Interpretations and owner-ratification items

1. **Migration/frozen-schema oracle: the effective `db.py` schema, not `database/schema.sql`.** ADR-0002 D2's letter names schema.sql; the delivered migrations align to what a fresh Python `create_all` + `_ensure_columns` actually produces (schema.sql defines a different, abandoned design — `legal_entities`, `working_paper_packs`). This is the only reading under which D2's intent ("existing data must open as-is") holds, and the fixture-equality tests prove the end state. The ADR text itself is NOT edited; owner: ratify the interpretation or direct reversion (an annotation on ADR-0002 D2 would settle it permanently).
2. **PostgreSQL `prev_entry_hash VARCHAR(80)`.** The reference's genesis marker (`GENESIS_BLOCK_` + 58 zeros — measured **72 characters** in both codebases) cannot fit the model's `String(64)`; latent in the reference (SQLite enforces no width, and it never posted on PG). SQLite keeps 64 byte-identical to the fixture; PG widens (80 = headroom over 72), pinned by test. Storage width only — no chain bytes touched.
3. **0007 `command_receipts` outside the fixture-equality surface** — bounded: exactly one named table excluded in `canonicalSchema`, asserted separately (shape + insert-if-absent PK semantics).
4. **`KindUnbalancedEntry`** — a store posting-gate refusal the reference does not have (defence-in-depth for the every-posted-entry-balances invariant). Strengthens a control; still a new behaviour the spec never named, so it rides the ratification list.
5. **BL-23 PostgreSQL scope** — `pg_dump` + the evidence tree is the operator procedure; the adapter refuses store-side PG backup (`ErrBackupUnsupported`) rather than shipping an unverified dump wrapper.
6. **BL-28 journal-ingress duplicate controls** — receipts are complete; business duplicate controls for regional webhook journals need the P5 ingress callers (nothing exists to control yet).
7. **b7d198c-era runbook** — ledgers last written 2026-10-17..21 are refused with the README's message; the operator opens them once with the frozen Python backend (bringing them to the current shape) and re-runs adoption. Now reachable and test-pinned instead of a wedging goose error.
8. **0005's down is a documented NO OP** (reversing the status rewrite would fabricate pack history) — carried from the migration record for explicit owner eyes.
9. **The committed binary oracle** (`python_ledger.db` + sidecars) and the `.gitignore` exception enabling it.
