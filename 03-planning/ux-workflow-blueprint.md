# UI/UX 流程藍圖

日期：2026-10-18。Draft，產品操作模式為 Operate。

來源：[SRC-0002 現有 UI](../01-inputs/2026-10-17-monolith-ui.md)、[SRC-0005 使用者方向](../01-inputs/2026-10-18-roadmap-request.md)、[SRC-0006 程式觀察](../01-inputs/2026-10-18-roadmap-code-baseline.md)、[SRC-0007 官方研究](../01-inputs/2026-10-18-roadmap-primary-sources.md)。此處是流程與驗收建議，沒有聲稱已做瀏覽器 UX 測試。

## 設計目標

會計人員打開系統後，能立即知道哪家公司、哪個期間、哪些事情需要自己判斷，並在作決定時看到相關證據與帳務影響。外部 AI Agent 是操作者之一；會計工作台要提供清楚的工作交接與監督。

保留 Monolith 的黑白基調、表格與數字排版。首頁主內容轉為待辦、例外與關帳進度。Sankey 和經營分析放在報表/分析入口，讓工作首頁優先顯示會影響帳務完成的事情。

## 角色與第一個任務

| 角色 | 進來要完成什麼 | 預設首頁 | 主要限制 |
| --- | --- | --- | --- |
| 記帳人 | 補文件、修正草稿、處理退回 | 我的待辦與待補件 | 不能核准自己需覆核的提案 |
| 覆核會計 | 看證據、判斷科目/稅務/期間、批准或退回 | 待覆核，按風險/期限排序 | 不把 AI confidence 當批准理由 |
| 財務主管/owner | 設定風險政策、安排關帳、處理重大例外 | 控制例外與關帳狀態 | 政策變更與帳務執行分開留痕 |
| 業務付款批准人 | 決定是否允許付款 | 待付款批准 | 與費用是否已認列分開；初版不執行銀行轉帳 |
| 系統管理員 | 管理登入、Agent 憑證及系統服務 | 存取治理 | 無默認帳務讀取、過帳或覆核權 |
| 外部 Agent | 透過 MCP 查資料、交提案、取得下一步 | 機器工具契約；人類可看執行紀錄 | 不能透過 UI/MCP 自升權限 |

## 資訊架構

| 一級入口 | 二級內容 | 使用目的 |
| --- | --- | --- |
| 工作台 | 我的待辦、待覆核、待補件、自動過帳抽查、失敗執行 | 開始及繼續工作 |
| 單據與交易 | 原始單據、應收、應付、收付款、往來對象 | 記錄經濟事實與結算 |
| 銀行對帳 | 匯入批次、流水、候選匹配、未達帳項、核對表 | 解釋帳面與銀行差異 |
| 帳簿與報表 | 日記帳、總帳、試算表、明細底稿、財務報表、分析 | 查看與追溯結果 |
| 月結 | 調整、固定資產/時間表、關帳清單、簽核快照、重開 | 完成指定期間 |
| Agent 與控制 | 連線、委任範圍、政策、執行紀錄、稽核、停用 | 管理外部 Agent 與自動化 |
| 設定 | 公司/帳套、期間、科目、制度、稅務身分、語言、個人偏好 | 維護上下文與規則 |

角色只看到有任務價值且獲授權的入口。UI 隱藏不代替伺服器授權。搜尋結果按公司與權限篩選，可深連結到原記錄；切換公司時清除前公司的選取與批次操作。

固定上下文列顯示公司、帳套、期間、本位幣、正式/示例、鎖帳狀態。公司/帳套切換需處理未提交內容，不能把同一草稿默默存入另一公司。

## 核心流程與頁面

### 1. 建立公司與接入 Agent

建公司 → 選適用制度與有效日 → 科目及期初匯入 → 核對 → 邀請記帳/覆核人 → 接入 Agent → 沙盒試做 → 決定啟用範圍。

- 公司、會計制度與稅務身分分欄；資料未知就保留未完成標記，不默認某種稅務身分。
- 期初匯入先預覽科目對照、借貸、控制科目與明細差異，列出修正入口；完成核對才啟用正式寫入。
- Agent 連線頁顯示公司、角色、可用工具、可讀文件範圍、到期日、最近活動及撤銷。授權頁使用人能理解的業務名稱，不只顯示 scope 字串。
- 新接入先完成測試交易，清楚標示沙盒與正式公司。自動政策預設未啟用；啟用前顯示具體模板及限制。
- 外部模型要取得哪些單據、欄位與公司資料，於授權時說明；無需把底層 JSON 或協定細節放在日常會計流程。

完成證據：使用者可接入 Agent、完成一筆測試、撤銷存取，並正確說明授權範圍。

### 2. 工作台與原始單據

首頁先列「需要你決定」「等待補件」「系統正在處理」「已自動過帳待抽查」。每項顯示公司、期間、金額、期限、來源、責任人及下一步；同一問題不在多個模組重複計數。

單據支援列表、原件預覽、結構化欄位及欄位定位。可見原件與 AI 抽取版本，人工修改保留差異。數電票/電子回單優先使用可取得的結構化原件；掃描件才需要 OCR。真實性查驗、商業用途及過帳狀態分開顯示。

狀態用具體描述：「原件已收取」「尚未查驗」「缺少交易對象」「等待覆核」「按政策已過帳」。避免用一個「完成」同時代表讀取、核准與過帳。

完成證據：使用者可找出兩張看似相同但業務識別不同的憑證，及同一憑證的重複上傳；能補件並回到原任務。

### 3. 覆核工作台

桌面以三欄為主要配置，窄螢幕改為保持上下文的頁籤。使用者可調整欄寬，不能縮到無法判斷金額或來源。

| 區域 | 顯示內容 | 要支持的判斷 |
| --- | --- | --- |
| 左，證據 | 原始文件、頁碼/欄位高亮、來源、查驗狀態、關聯合約/流水 | 這筆事實有根據嗎？ |
| 中，分錄 | 對象、日期、期間、完整借貸行、原幣/本位幣、稅額、總額及差額 | 這樣記錄是否正確？ |
| 右，理由與控制 | 規則結果、需判斷項、缺件、政策版本、與上次版本差異、報表影響 | 為何需要我覆核？批准後會發生什麼？ |

底部固定操作為「退回補件」「拒絕」「核准並過帳」或該角色實際可執行的動作。鍵盤捷徑不能單一按鍵無意提交重大操作。AI 理由顯示可檢查的來源及簡短業務說明，不要求或展示模型內部思維鏈。

人工修改建立新版本並重新驗證；原製單者/批准關係依規則重新計算，不能沿用已失效批准。批准綁定具體版本，送出時若內容已改變，顯示差異並重新覆核。

批次覆核只處理同質且可清楚檢查的項目。顯示選取範圍、筆數、總額及每項結果，例外不隱藏在總數中。不可把頁面上的「全選」誤解成所有搜尋結果。

完成證據：使用者能識別金額、科目、期間及稅務各一個刻意植入的錯誤，並完成修改/退回；不能批准自己不可批准的提案。

### 4. 自動過帳與政策治理

每筆自動分錄可打開「為何自動過帳」，看到命中模板、限制、文件/合約、政策版本與實際執行者。不以信心 99% 作主標籤；信心若顯示，要明確是模型估計而非核准。

政策頁包含可適用公司、科目組合、交易模板、對象、單筆/累計上限、有效日期、抽查比例、批准者及最近變更。新政策先顯示 shadow 比較結果；啟用前有影響預覽。

停用可針對單一模板、Agent 或整家公司。停用後 UI 明確說明「後續提交轉人工；已過帳紀錄保留」。發現錯誤可建立更正並查看同一政策的其他交易。停用與憑證撤銷的權限、效力和執行中工作的處理方式需要一致。

### 5. 銀行對帳與收付款

- 左側銀行結單、右側帳面記錄；選取後顯示同/異點、差額與日期。相同金額只是證據之一，不默認就是同一交易。
- 分別提供「匹配已有記錄」「建立待覆核調整」「記錄未達帳項」。按鈕寫明結果，不能共用模糊的 Resolve。
- 一對多/多對一顯示已分配與未分配金額；費用、退款與內部轉帳需選正確事件類型。
- 應付畫面分開「已認列」「付款已批准」「已記錄付款」「銀行已核對」，付款記錄不暗示已發起轉帳。
- 未達項顯示原因、憑據、負責人、預計清除期間及覆核結果；舊項逾期進待辦。

完成證據：使用者可以處理部分付款、含手續費收款及跨期未達付款，且不重複產生收入/費用。

### 6. 月結與報表追溯

關帳首頁列四區：系統阻擋、待人工判斷、已解釋時點差異、已完成。自動核對結果不能手動勾成通過。人工判斷項需理由、附件、負責人及覆核。

點擊報表數字可依序看到報表映射 → 科目/底稿 → 分錄 → 原件及批准。返回時保留期間、篩選及捲動位置。表頭與匯出都包含公司、準則/規則版本、期間、幣別、生成時間及帳本快照。

簽核畫面預覽期間、未解阻擋數、允許的時點差異、簽核人及將鎖定的版本，再執行 MFA。重開顯示原因、哪些報表/後續期間需要重算，並保留原簽核快照。

完成證據：會計能找到關帳被擋的實際原因、修正後返回、簽核正確版本，並從報表追到任一抽查文件。

## 所有頁面都要處理的狀態

| 情況 | UI 行為 |
| --- | --- |
| 首次空白 | 解釋尚缺哪一步，提供建立公司、匯入或接入的下一步；不填假數字 |
| 讀取中 | 保持版面與公司/期間上下文，讀取完成後才顯示正式結果 |
| 儲存中 | 顯示正在提交的具體項目，避免重複點擊；可繼續安全的其他工作 |
| 成功 | 收到服務端確認才顯示已過帳，附分錄編號；草稿儲存不能叫過帳 |
| 網路逾時 | 顯示「正在確認提交結果」，用原命令 ID 查詢，不要求使用者盲目重做 |
| 版本衝突 | 顯示伺服器新版本與本地變更差異，保留輸入，讓使用者重新選擇 |
| 權限不足 | 解釋缺少哪個業務角色及可交給誰，不洩漏其他公司資料 |
| 鎖帳 | 顯示期間狀態、可用更正流程；不能把已鎖期間看似編輯成功 |
| 缺資料/驗真失敗 | 列出具體欄位或證據問題，能補件並恢復任務 |
| 批次部分完成 | 列成功/未完成及原因，重試只對未完成項；若採全批原子則明示全批未提交 |
| Agent 失敗/取消 | 區分未開始、執行中、已提交、失敗；取消不承諾撤銷已過帳交易 |
| Demo/不支援能力 | 持續顯示來源或限制；不提供會被誤解為實際報稅/支付的成功提示 |

財務高風險操作提供檢查、修正、確認或依會計程序更正的能力。普通草稿保存保持直接，不增加沒有資訊的確認彈窗。[W3C SC 3.3.4](https://www.w3.org/WAI/WCAG22/Understanding/error-prevention-legal-financial-data.html)

## 語言、可讀性與裝置

- v0.6 起完成中國大陸核心流程的簡體中文及英文，v1.1 加入繁體中文。欄位、錯誤、審批、MFA、日期、匯出與空白狀態都在翻譯範圍內；語言不自動改變法域。
- 金額右對齊、使用等寬數字、清楚顯示貨幣與負數。日期和會計期間分開；跨幣別資料同時顯示原幣與本位幣。
- 保留 Monolith 風格；關鍵操作文字與金額避免目前部分過小的密集標籤。以約 14–16px 正文為原型起點，實測密度及縮放。
- 目標為核心流程 WCAG 2.2 AA：鍵盤、可見焦點、欄位標籤、錯誤摘要、螢幕閱讀器、對比、縮放及非純顏色狀態。這是驗收目標，需完整檢查才可宣稱達成。
- 桌面支援大量分錄與證據並列；平板可覆核。手機先支援拍攝/上傳、待辦與詳情，複雜批次及關帳工作採已驗證的裝置範圍，不把密集表格硬縮成難讀畫面。
- 大量資料採分頁/虛擬列表與伺服器搜尋；導航位置、選取範圍、加載中及空結果保持可理解。

## 設計驗收與迭代節奏

每個版本先選 3–5 個關鍵任務，做一輪原型測試，實作後做一輪完整流程驗收。記錄錯誤、完成時間、需要協助之處及使用者對狀態的理解，修正後只重測受影響流程。

| 版本 | 必測任務 |
| --- | --- |
| v0.5 | 建立公司、匯入期初、辨認公司/期間、處理衝突 |
| v0.6 | 接入/撤銷 Agent、辨認自動或人工結果、查證據、退回與覆核、停用政策 |
| v0.7 | 部分收付款、重複單據、一對多匹配、合法未達項 |
| v0.8 | 找到關帳阻擋、追溯報表、MFA 簽核、重開與更正 |
| v0.9 / v1.0 | 真實角色跨頁完成月結、無障礙檢查、異常/恢復操作 |
| 每個新市場 | 語言與術語、企業制度選擇、當地憑證/稅務工作表、當地會計月結 |

每輪建議 5–8 名代表使用者，至少涵蓋記帳與覆核角色。初始任務成功率目標 ≥90%，且無不可恢復的財務誤操作。小樣本只作設計改進證據，不宣稱全體使用者都能正確操作。驗收材料存入 `07-reviews/` 並由對應需求包引用。
